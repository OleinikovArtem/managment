# UI/UX-аудит Party Bank Manager

Дата: 2026-11-02

Режим: audit + critique + refactor brief. Приложение — локальный desktop-first
web app для быстрого ввода рейдов, предметов и финансовых операций.

- `screenshot`: просмотрен пользовательский скриншот страницы деталей рейда
  `Снимок экрана 2026-11-02 211559.png`. Он подтверждает визуальную иерархию,
  расстояния, контраст и структуру видимых блоков.

- `automated`: `check_state_coverage.ts` просканировал 126 файлов и сообщил
  `passed: true`, все восемь маркеров состояний найдены.
- `Manual`: рекомендации по удобству, приоритету действий и общей визуальной
  системе. Это не замена browser/DOM/axe-проверке.

Не запускались браузерный smoke test, Lighthouse, axe и DOM-инспекция. Поэтому
ниже нет утверждений об их результатах.

Системный первый проход редизайна выполнен после аудита: обновлены общие токены,
карточки, кнопки, поля, select, checkbox, focus states, боковая навигация и
адаптивные отступы. В форме рейда добавлен локальный `ItemCombobox` с keyboard
навигацией и удалением новых строк; полноценный `LootDropRow` с progressive
disclosure дополнительных полей остаётся следующим этапом.

Формы редких действий создания участника и предмета теперь скрыты по умолчанию:
они открываются одной кнопкой внутри основной поверхности списка. Это оставляет
частый сценарий просмотра и редактирования компактным.

## Итог

Текущий интерфейс функционален, но визуально и по рабочему потоку ощущается как
набор отдельных CRUD-форм. Главный сценарий пользователя — «открыть рейд,
добавить несколько предметов и быстро исправить количество» — требует слишком
много переключений внимания. Главная цель редизайна: один спокойный экран рейда,
где предмет добавляется поиском, сразу превращается в компактную редактируемую
строку, а вторичные поля раскрываются только по запросу.

Оценка: **Needs work**, без подтверждённых Critical-проблем.

## Предлагаемый главный сценарий

1. Пользователь открывает «Новый рейд» и видит название/время, состав и одну
   пустую область «Лут».
2. В поле «Добавить предмет» вводит `life`; результаты появляются под полем.
3. Enter выбирает предмет и создаёт строку:
   `Top-grade Life Stone - Lv. 76   Количество [ 5 ]   ⋯`.
4. Фокус возвращается в поле добавления, поэтому следующий предмет вводится
   без клика по кнопке.
5. Количество меняется прямо в строке; удалить новую строку можно одним действием.
6. Комментарий и screenshot остаются в меню «Ещё», чтобы не перегружать строку.
7. Внизу одна основная кнопка «Сохранить рейд», рядом тихая «Отмена».

## Wireframe

Desktop:

```text
┌ Новый рейд                                      ┐
│ Название [ Zaken ]   Дата [ 02.11 20:11 ]       │
│ Состав рейда  [ Hunterok ✓ ] [ Korsa ✓ ] ...     │
│                                                  │
│ Лут                              3 предмета      │
│ [ 🔎 Добавить предмет…                         ] │
│ ┌ Top-grade Life Stone - Lv. 76     [ 5 ]  ⋯ 🗑 ┐ │
│ ┌ Scroll of ...                      [ 2 ]  ⋯ 🗑 ┐ │
│                                                  │
│ [Сохранить рейд]  Отмена                         │
└──────────────────────────────────────────────────┘
```

Compact width: search stays full-width; each item row remains two columns
`name / quantity + actions`; metadata wraps under the name; no two-column form.

## Компонентная модель

### `ItemCombobox`

- `role=combobox`, `aria-expanded`, `aria-controls`, `aria-activedescendant`;
- minimum target height 40px on desktop, 44px when touch width is detected;
- debounce 150–250ms, results 5–8 items, keyboard selection;
- loading label «Ищем предметы…», empty «Ничего не найдено», error «Не удалось
  загрузить каталог» с повтором;
- footer result «Создать новый предмет» открывает небольшой side sheet, не уводя
  пользователя с рейда;
- после выбора поле очищается и сохраняет фокус.

### `LootDropRow`

- `itemId` и количество — всегда видимы;
- комментарий и screenshot — progressive disclosure через «Ещё»;
- удаление — иконка с текстовой accessible label и undo toast для новых строк;
- для существующей исторической записи показывать понятный статус и правила
  блокировки вместо скрытого disabled-контрола;
- `quantity` с `min=1`, `step=1`, корректным `aria-describedby` ошибки.

### `RaidForm`

Оставить `react-hook-form` и `useFieldArray`, но использовать `append` только
после выбора item и `remove(index)` для новых строк. Серверную транзакцию не
менять: это только улучшение композиции и ввода.

## State matrix для нового ввода лута

| Состояние | Видимое поведение |
| --- | --- |
| Loading | Skeleton одной строки или spinner внутри combobox, layout не прыгает |
| Empty | Подсказка «Введите название предмета»; при запросе — «Ничего не найдено» |
| Error | Inline сообщение и «Повторить»; уже добавленные строки сохраняются |
| Disabled | Поле и удаление заблокированы, рядом причина (`финансовая история зафиксирована`) |
| Focus | Видимый ring, выделенный active option, корректный tab order |
| Hover | Подсветка строки и action без изменения размеров |
| Selected | Выбранный результат превращается в строку, focus возвращается в поиск |
| Submitting | Одна кнопка показывает «Сохраняем…», строки остаются читаемыми |
| Success | Toast + переход к деталям рейда; сохранённые строки видны без повторного ввода |

## Минималистичная визуальная система

- Сохранить тёмную основу, но уменьшить количество обводок: поверхность рейда,
  мягкие разделители, один primary accent для активного действия.
- Не добавлять градиенты, декоративные иллюстрации и новые равноправные кнопки.
- В строке лута использовать один основной акцент, а цвет Adena оставить
  семантическим сигналом суммы.
- Заголовок секции — 16px/600, основной текст — 14–15px, helper — 12–13px;
  не использовать helper text как основной способ объяснить действие.
- Имена предметов и ники — `text-foreground`; вторичные технические детали — muted.
- Числа количества и Adena — `tabular-nums`, правое выравнивание.

## План внедрения

1. Сначала создать общий `ItemCombobox` и `LootDropRow`, не меняя server action.
2. Подключить их к `RaidForm`; добавить remove, focus return и state matrix.
3. Добавить «Создать предмет» в side sheet с возвратом выбранного результата.
4. Упростить карточки создания рейда и каталога, оставить только нужные поля в
   первом экране.
5. Выполнить browser smoke на `/raids/new` и `/raids/[id]/edit` в desktop и
   320px; проверить keyboard-only сценарий и reduced motion.
6. Снять новый скриншот и провести regression audit по этой записке.

## Что не делать

- Не превращать экран в таблицу с десятью колонками.
- Не добавлять отдельные кнопки для каждого вторичного поля.
- Не скрывать удаление за несколькими меню, если строка ещё не сохранена.
- Не заменять локальный поиск внешним сервисом без отдельного согласования.
- Не менять финансовую модель или транзакции ради визуального редизайна.

## Основание рекомендаций

Web app skill рекомендует держать частые фильтры возле данных, использовать
detail panes для повторного редактирования и проверять loading/empty/error/
disabled/focus/selected/submitting/success. UX audit skill требует маркировать
каждое наблюдение типом доказательства и не делать DOM-утверждений по одному
скриншоту. Apple HIG использован как переносимый ориентир: поиск должен иметь
заметное место и подсказки, текстовые поля — явные labels и динамическую
валидацию, списки — короткие строки и явные действия. Для web-приложения это
адаптировано к ARIA, keyboard focus и CSS breakpoints, а не к нативным iOS
компонентам.
