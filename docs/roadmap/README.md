## Общие требования

- Переиспользовать `PartyMember`, `Instance`, `Raid` и серверную проверку принадлежности группе.
- Учёт прохождений основан на PRESENT рейдов группы; самостоятельные походы не подавляют предупреждения. Все активные персонажи входят в roster.
- Будущие отправители используют согласованное расписание календаря. Требования к окну Telegram определяются отдельно; ежедневный Подвал сейчас исключён из предупреждений веб-календаря.
- Денежные данные — только адресату после подтверждённой привязки. Источник — существующие BigInt-расчёты и проводки; финансовые правила не меняются.
- Для новых сценариев нужны loading, empty, error/retry, pending, отказ доступа и релевантные конфликты; ошибки сохраняют ввод.
- Новые пользовательские сценарии сопровождаются Playwright E2E; перед коммитом фичи запускается полный Chromium. Используются существующие локальные аккаунты и Docker PostgreSQL, каталог предметов сохраняется.
- Next.js API проверяются по документации установленной версии. Перед изменением persistence читается ARCHITECTURE.md; финансовая схема не полностью представлена в миграциях.
- После реализации требования текущего поведения переносятся в канонические документы, завершённые планы удаляются.

## За пределами scope

Чтение игрового клиента, гарантия фактического прохождения, инвентарь конкретного СА,
новые расчёты долей, переводы Adena через Telegram и создание рейдов командами бота.
