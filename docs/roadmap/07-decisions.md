# Решения и вопросы будущих фич

Действующий календарь описан в [PROJECT_SPEC.md](../../PROJECT_SPEC.md#календарь-инстансов).
Расписание предоставлено пользователем и задано в коде; оно не требует импорта
demo и не хранится в БД. Планы ниже не описывают реализованное поведение.

## Согласованные границы

- Telegram-напоминания и личный бот — следующие этапы; веб-предупреждения уже работают.
- Групповые напоминания охватывают всех активных персонажей без исключений и ограничений сохранённым составом. Прохождение определяется по PRESENT в рейдах группы.
- Для личного бота нужен аккаунт и membership приложения. ADMIN/OWNER назначает одного или нескольких персонажей, игрок подтверждает Telegram-привязку.
- Денежные сведения доступны только адресату в личном чате после подтверждения связи.
- Таблица СА ещё ожидается. Примеры СА остаются демонстрационными и не публикуются как проверенные игровые правила.

## Предлагаемые новые сущности

Это требования к будущей разработке, не готовая Prisma-схема.

| Сущность             | Связи и инвариант                                                                              |
| -------------------- | ---------------------------------------------------------------------------------------------- |
| Правило СА           | Контекст сервера, instanceId, bossKey, переход уровня, условия, источник/revision              |
| Назначение персонажа | partyId + memberId → userId; один действующий владелец персонажа                               |
| Telegram-привязка    | botId + Telegram user ID + назначение; pending/active/revoked, отдельный одноразовый challenge |
| Подписка и задание   | Получатель, scope, период/окно, часть сообщения, статус доставки/lease; уникальные ключи       |
| Отсутствие           | Группа, персонаж, UTC-интервал, исходная timezone, автор и ограниченно видимая заметка         |

`PartyMember` принадлежит группе. Межгрупповая синхронизация персонажа автоматически
не подразумевается. Календарные статусы читаются из рейдов; таблица отдельных
закрытий для Telegram не требуется.

## Ограничения безопасности и доставки

- Нельзя назначать персонажа по совпадению ника или Telegram username; нужны стабильные ID и подтверждение.
- Команды маршрутизируются отдельно от финансового импорта; исходящий чат не заменяет chatId источника BOHPTS.
- Перед каждой отправкой повторно проверяются membership, назначение, подписка и актуальное участие в рейдах.
- Повторы scheduler защищаются уникальными заданиями и lease; потеря ответа Telegram допускает статус unknown, обещать exactly-once нельзя.
- Отсутствия и будущие календарные коррекции не меняют финансовые доли и исходные снимки.
- Проверка синтетическим Telegram API и реальная доставка — разные проверки; тесты не отправляют сообщения реальным адресатам.
