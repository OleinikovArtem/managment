# F07. Объединённый раздел «Походы»

Статус: будущая фича, не реализована.

## Цель

Объединить страницы рейдов и календаря в один раздел «Походы» с двумя режимами:
«Календарь» для обзора по датам и «Список» для поиска и просмотра истории.
Переключение режима меняет представление, а не данные.

Текущие правила и поведение описаны в [PROJECT_SPEC.md](../../PROJECT_SPEC.md#календарь-инстансов)
и [PROJECT_SPEC.md о рейдах](../../PROJECT_SPEC.md#рейды-и-исторические-снимки).
Это ТЗ описывает будущую навигацию и объединение интерфейсов.

## Прототип

Desktop:

```text
┌─────────────────────────────────────────────────────────────────────┐
│ Походы                                     [ + Записать поход ]     │
│ История рейдов группы                                               │
│                                                                     │
│ [ Календарь ] [ Список ]        [Инстанс ▾]                         │
│                                                                     │
│ До отката меньше 24 часов: Закен · Близы · Тиата                   │
│ ‹   Ноябрь 2026   › [Сегодня]      [Показывать откаты] [Расписание]│
│                                                                     │
│                   Сетка Пн — Вс                                     │
│   походы выше откатов; выбор дня открывает панель деталей           │
└─────────────────────────────────────────────────────────────────────┘

Список:
┌─────────────────────────────────────────────────────────────────────┐
│ [ Календарь ] [ Список ] [Инстанс ▾] [Период ▾] [Поиск рейда…]    │
│ 18 рейдов                                                           │
│ Сегодня (2)                                                         │
│ рейд и инстанс                         участники · лут · время      │
│ Вчера (3)                                                           │
│ …                                                                   │
│ [Назад]                         1 / 3                         [Вперёд]│
└─────────────────────────────────────────────────────────────────────┘
```

На мобильном заголовок и переключатель остаются сверху, фильтры складываются
в столбик, календарная сетка сохраняет компактный вид. Панель дня открывается
на весь экран, как сейчас.

## Требования

### Страница и навигация

- Один пункт боковой навигации «Походы» ведёт на /raids. Отдельный пункт
  «Календарь» удаляется.
- /raids без параметра режима открывает календарь. Поддерживаются
  /raids?view=calendar и /raids?view=list.
- Старый /calendar перенаправляет в режим календаря и сохраняет month, day,
  instance, member и resets. Закладки остаются рабочими.
- Текущий режим и фильтры отражаются в URL. Переключение режимов поддерживает
  браузерные Back/Forward и не теряет состояние скрытого режима.
- Список хранит q, period и page. Календарь хранит month, day, instance,
  member и resets. Чужие параметры не меняют фильтры другого режима.
- Переход к деталям и созданию рейда сохраняет контекст раздела, чтобы возврат
  восстанавливал выбранный режим и его фильтры.

### Общие элементы и фильтры

- Заголовок «Походы», короткое описание и действие «Записать поход» в обоих
  режимах. Действие видно только пользователям с правом создать рейд.
- Общий фильтр инстанса фильтрует и календарь, и список. Для выбора применяется
  стабильный instanceId; список передаёт его вместе с названием.
- Фильтр персонажа доступен только в календаре. Поиск и фильтр периода доступны
  только в списке. Значения сохраняются при переключении.
- Сброс фильтров очищает фильтры текущего режима и общий фильтр инстанса.

### Режим «Календарь»

- Сохранить месячную сетку, переключение месяцев, переход к сегодня, справочные
  откаты, недельную таблицу, предупреждения и панель дня.
- Не менять правила расписания, фильтрации походов, общих откатов, окна
  предупреждений и исключения ежедневных инстансов.
- Оставить порядок походов перед откатами и скрытие совпавшего отката в ячейке.
- Ссылки из панели дня ведут к текущим деталям рейда. Запись из дня доступна
  менеджерам и открывает ту же форму с предзаполненной датой.

### Режим «Список»

- Сохранить поиск по названию рейда и инстансу, фильтр периода, группировку
  по датам, счётчик, пустое состояние, пагинацию и локальное время.
- Переключение режимов сохраняет поисковую строку, период и страницу. Если после
  обновления данных страница вышла за пределы результатов, показать последнюю
  доступную страницу.
- Рейд открывает существующую страницу деталей. Финансовые ограничения не меняются.

### Доступность и состояния

- Переключатель режимов доступен клавиатурой, объявляет выбранный режим и сохраняет
  фокус при смене содержимого.
- Для каждого режима есть подходящий skeleton. Ошибка загрузки имеет повтор;
  её нельзя показывать как успешный пустой результат.
- Пустой список по фильтру позволяет сбросить фильтры.
- Проверить desktop 1440 px, mobile 390/320 px и shell 768/1024 px. Не должно
  появиться горизонтальной прокрутки или обрезанных действий.
- Сохранить управление сеткой клавиатурой, Escape и возврат фокуса из панели дня.

## Этапы реализации

1. **Маршруты и состояние URL.** Нормализовать режим, добавить перенаправление
   /calendar с сохранением параметров, сохранить контекст переходов к деталям
   и форме. Проверить прямые URL и Back/Forward.
2. **Общая оболочка.** Объединить заголовок, переключатель, действие создания
   и стабильный фильтр инстанса. Календарь и список оставить отдельными режимами.
3. **Календарь.** Перенести действующий экран без изменения расчётов и поведения.
   Проверить месяц, день, откаты, предупреждения, старые ссылки и мобильную панель.
4. **Список.** Встроить существующие поиск, фильтры, группировку и пагинацию.
   Перевести фильтр инстанса с отображаемого имени на стабильный ID.
5. **Состояние и адаптивность.** Обеспечить независимое сохранение фильтров,
   общий фильтр, доступность клавиатурой, skeleton и error/retry обоих режимов.
6. **Удаление старого интерфейса.** Удалить прежнюю страницу календаря после
   установки redirect. Перенести реализованные требования в канонические
   документы, удалить завершённые шаги ТЗ.

## Приёмка и E2E

Playwright Chromium покрывает в e2e/raids-calendar.spec.ts:

- Календарь открывается по умолчанию; список открывается по вкладке и прямому URL.
- Оба режима сохраняют собственные фильтры, общий инстанс синхронизирован;
  Back/Forward восстанавливает URL и выбранное содержимое.
- Старый /calendar сохраняет месяц, день, инстанс, персонажа и видимость откатов.
- Список фильтрует по ID инстанса, запросу и периоду; пагинация корректно
  сбрасывается и ограничивается.
- Создание разрешено только менеджеру и создаёт один рейд; он виден в обоих режимах.
- Ссылки на рейд ведут к тем же деталям; член группы не видит действие создания.
- Данные другой группы недоступны в обоих режимах и в панели дня.
- Empty, filtered empty, loading и error/retry проверены отдельно.
- Клавиатура переключает режим, сетка и панель дня сохраняют ожидаемый фокус.
- 320/390/768/1024/1440 px без горизонтальной прокрутки и потери действий.

Переиспользовать существующие E2E fixtures и локальную БД. Каталог предметов
не изменять. Перед коммитом feature выполнить полный Chromium набор.

## Не входит в scope

Изменение правил отката или предупреждений, запись будущих дат откатов, ручные
закрытия, Telegram-уведомления, планирование рейдов, финансовые расчёты,
исторические снимки и переписывание логики фильтров списка.
