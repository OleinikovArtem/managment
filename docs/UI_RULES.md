# Правила интерфейса

## Назначение

Интерфейс предназначен для ежедневной работы с рейдами, добычей и Adena.
Приоритет — понятная иерархия, быстрое внесение данных и читаемая история.
shadcn/Base UI и Tailwind — инструменты реализации, а не готовый визуальный шаблон.

## Визуальная основа

Источник токенов — `src/app/globals.css`, локальных правил Raid Detail —
`src/features/raids/raid-detail-view.css`.

| Назначение                 | Значение                                                  |
| -------------------------- | --------------------------------------------------------- |
| Фон                        | `#101112`                                                 |
| Текст / вторичный текст    | `#f0f1f2` / `#a8afb6`                                     |
| Поверхность формы          | `#17191b`                                                 |
| Разделитель / граница поля | `#2b3035` / `#68717a`                                     |
| Focus                      | `#9ec5ff`                                                 |
| Ошибка                     | `#ff9898`                                                 |
| Акцент данных / Adena      | `#e6be67` для акцента; Adena использует `hsl(45 92% 56%)` |
| Шрифт                      | Segoe UI, system-ui, системные fallback                   |

Обычный h1 — 24 px; Raid Detail использует 30 px на desktop и 24 px на mobile.
Основной текст — 14–16 px, вторичные метаданные — 12 px. Суммы используют tabular nums.
Цвет не заменяет текстовый смысл: долг, переплата, остаток и ошибка подписываются.

Содержимое ограничено 1280 px. Общие отступы — 16 px на mobile, 24 px на tablet,
32 px на desktop; секции разделяются пространством и тонкими линиями.
Поверхность нужна для ввода/редактирования или всплывающего контекста.
Не оборачивать каждую строку и метрику в карточку; не добавлять вложенные рамки,
декоративные градиенты, иконки или тени без функции.

## Навигация

Четыре основных раздела: Обзор, Рейды, Финансы, Группа. Лут, каталог и настройки —
отдельные вторичные пункты. Финансы объединяют маршруты выплат и операций;
Группа — участников и составы. Вложенная страница сохраняет активность раздела.

Desktop sidebar включается от 1024 px. Ниже — компактный header, четыре ссылки
и меню всех разделов. Мобильное меню использует доступный диалог с удержанием
фокуса, закрытием по Escape и возвратом к инициатору.

## Действия и раскрытие

- На странице одна ясная основная задача: создать рейд, добавить участника,
  записать продажу или передачу. Частые действия остаются подписанными и видимыми.
- Редактирование, отключение и редкие действия строки группируются в `ActionMenu`.
  Trigger виден постоянно, имеет доступное имя и работает с клавиатуры.
- История, доли, дополнительные фильтры и комментарии раскрываются по запросу.
  Не скрывать действия продажи/передачи в меню ради минимального вида.
- Форма продажи и панель передачи удерживают клавиатурный фокус и после Escape
  возвращают его к вызвавшей кнопке. Инициатор передаётся в `finalFocus` Base UI.
  При сетевой ошибке форма остаётся открытой с черновиком и сообщением о повторе.
- Ручная продажа вводится только со страницы «Лут» в модальном окне поверх сетки;
  открытие формы не меняет размеры и положение плиток. Telegram продолжает
  автоматически регистрировать распознанные продажи.
- Опасные действия отделены; очистка требует ручного подтверждения. Исторические
  финансовые данные не получают обычного действия удаления.
- Сброс в настройках показывается непосредственно во вкладке Reset с пустым начальным
  выбором сущностей, зависимостями и read-only preview количества записей. Зависимости
  добавляются автоматически и подписаны; снять их можно через исходную сущность.
  Изменение выбора очищает введённое подтверждение. Общий каталог не удаляется;
  последнее подтверждение проходит через общий диалог.

## Композиция экранов

| Экран          | Иерархия                                                                                                                                 |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| Обзор          | Банк и остатки → последние рейды → раскрываемая аналитика                                                                                |
| Raid Detail    | Название/время → сводка → добыча и время → admin-кнопка добавить/удалить добычу → карточки PRESENT с ником и классом сбоку или ниже      |
| Список рейдов  | Заголовок и действие → поиск/фильтры инстанса и периода → группы дат → ссылки с составом, добычей и временем                             |
| Создание рейда | Компактная строка инстанс/дата/Stage → участники и шаблон → плитки лута → итог и сохранение; своё название раскрывается по необходимости |
| Выплаты        | Банк, начисления и переплаты → поиск/тип остатка → плитки участников и inline-передача                                                   |
| Операции       | Поиск/тип → хронологический журнал → раскрытая точная сумма и компактная сетка долей                                                     |
| Участники      | Поиск/статус → ник и иконки Main/Subclass с названиями → редактирование Main и четырёх слотов                                            |
| Составы        | Выбор сохранённого состава → roster; builder выбирает Main, Subclass или профессию каталога для каждого слота                            |
| Каталог        | Поиск/категория → количество результатов и добавление → строки и пагинация                                                               |
| Лут            | Поиск/фильтры → сетка поступлений от новых к старым → остаток, сумма продаж, ссылка на рейд и модальное ручное внесение продажи          |
| Настройки      | Вкладки «Группа», «Telegram», «Reset»; настройки группы в первой, выборочный сброс с серверным preview — в последней                     |

Списки сохраняют длинные названия и читаемую связь значения с подписью.
Не обрезать единственный источник важного имени или точной финансовой суммы.
Короткая сумма помогает сканировать список; полная доступна в деталях, а не только hover.

Форма каталога предлагает ранги «Не указан», S84, S80, S, A, B, C и D. Старое
нестандартное значение остаётся выбранным при редактировании до явной замены;
`itemSubtype` и `gameVersion` сохраняются, хотя их поля скрыты в этой форме.

В Raid Detail добыча отображается плитками с локальными иконками и временем поступления;
продажи, остатки, история и действия записи продажи на этой странице не показываются.
На странице «Лут» по умолчанию каждая запись добычи — отдельная плитка с локальной
иконкой; чекбокс «Объединить одинаковые» сводит их по предмету. Плитки имеют
одинаковую двухстрочную область имени; длинные названия обрезаются с многоточием,
а полное имя доступно через tooltip. Полностью проданные поступления получают серое
оформление и текстовую метку «Продано». Статус «Продано» показывается, только когда
весь остаток карточки распродан; «Частично продано» — когда продана часть. Продажи
и остатки видны на карточке. Цена над суммой — средняя за штуку; hover показывает
количество и цену каждой продажи, ниже остаётся полная сумма. В объединённой карточке
сначала доступно к продаже самое раннее поступление с остатком; количество можно
продать сразу через несколько поступлений в пределах общего остатка. Поле ограничивает
ручной ввод и сервер повторно проверяет его под блокировкой группы. Фильтры «Все»,
«Проданные» и «На продаже» разделяют
полностью проданные предметы и те, у которых ещё есть остаток. Ручная продажа
открывается общим модальным окном поверх сетки и не меняет layout; закрытие по Escape
и фокус остаются под управлением `EditorDialog`. OWNER/ADMIN видят ссылку на форму,
где можно добавить/удалить добычу незаблокированного рейда. Карточки состава показывают
только участников со статусом PRESENT, их ник и исторический класс без Main/Subclass.
В модальной форме поле количества узкое, его максимум равен доступному остатку
выбранного поступления, а в режиме объединения — суммарного остатка по предмету;
сервер дополнительно проверяет это ограничение. Поля идут
вертикально, чтобы подписи, сумма и дата не конкурировали за узкую колонку.

Список рейдов использует взаимоисключающие локальные календарные группы: сегодня,
вчера, 2–7 дней назад, 8–30 дней назад и более ранние месяцы; будущие даты имеют
отдельную группу. Поиск, инстанс и период расположены над списком и сочетаются.
Финансовые страницы сохраняют вкладки «Выплаты» и «Операции», показывают суммы
табличными цифрами и используют подписанные сегментные фильтры. Остаток каждого
участника отображается компактной кнопкой-плиткой. По клику открывается боковая панель
с получателем и редактируемой суммой; начальная сумма рассчитывается от остатка банка,
ограничивается суммой к выплате и округляется вниз до целого миллиона. Доли в открытой операции
размещаются плотной сеткой малых плашек с ником и точной суммой.
Не превращать сводные метрики в отдельные декоративные карточки.

В панели выплаты черновики суммы, даты, комментария и его раскрытия сохраняются в памяти
страницы отдельно для каждого получателя при закрытии панели и переключении между ними.
После успешной передачи черновик получателя очищается; уход со страницы его не сохраняет.
Ввод не пересчитывается автоматически при обновлении остатка. Панель использует короткий
переход открытия/закрытия и отключает его при `prefers-reduced-motion`.

В раскрытом активном участнике доступны редактирование его Subclass, названия,
класса, роли и заметки. Main и слоты редактируются в форме участника. Изменение
устаревшей записи профиля не перезаписывает актуальные данные: форма сообщает о
конфликте и остаётся открытой.

## Формы и состояния

В форме рейда StageSwitcher меняет только локальный черновик; постоянный default
группы находится отдельно в Settings. Смена Stage/Instance и ошибки обновления
рекомендаций сохраняют все поля, профили, количества и комментарии. Не использовать
reset/remount или router.refresh для переключения. Выбранные предметы остаются
плитками даже вне нового набора, рекомендации ничего не преселектят.
Grid содержит 4–6 плиток на desktop, на mobile адаптируется без overflow;
плитка «+ Добавить предмет» видна и при пустых рекомендациях. sortOrder не означает
вероятность: нет выдуманных процентов/редкости и названия «Дроп по вероятности».

У поля есть label, обязательность и понятная ошибка. Необязательные комментарии
и классификацию можно раскрывать. Некорректная дата остаётся видимой.
Не менять смысл денежного ввода, parser или prefill в рамках визуальной правки:
действует контракт из [PROJECT_SPEC.md](../PROJECT_SPEC.md#денежный-ввод).

При ожидании БД сохранять постоянную оболочку, заголовок и навигацию; для списка и
сводки показывать скелетоны подходящей геометрии, чтобы данные не сдвигали экран.
Не показывать нулевые суммы до завершения загрузки. Показывать pending, блокировать
повторную отправку, сохранять введённые значения
при ошибке. Успех обновляет соответствующие страницы и остатки. Empty state
объясняет отсутствие данных и следующий доступный шаг; загрузка сохраняет
структуру страницы; ошибка предлагает повторить; отсутствующая запись — путь назад.
Не показывать сырые SQL/Prisma детали пользователю.

## Адаптивность и доступность

- Поля на узких экранах — минимум 16 px, touch controls — минимум 44 px.
- Корневой документ резервирует стабильное место под вертикальный scrollbar, чтобы
  появление прокрутки при раскрытии содержимого не смещало интерфейс по горизонтали.
- Учитывать доступную ширину контента. Raid Detail складывает колонки при ширине
  контейнера ≤800 px; отсутствие overflow само по себе не доказывает удобство.
- Сохранять читаемость длинных roster, нескольких поступлений, частичных продаж,
  больших сумм и переплат. Не превращать mobile в уменьшенную desktop-таблицу.
- Использовать semantic headings, labels, native details и `aria-current`.
  Видимый focus обязателен; состояние не передаётся только цветом.
- Поддерживать клавиатуру, Escape для диалогов, focus management и reduced motion.

## Календарь и общие компоненты shadcn

Календарь использует существующий shadcn `base-nova` на Base UI. Общие EditorDialog,
ConfirmationDialog, SidePanel и ActionMenu — адаптеры над Dialog, AlertDialog, Sheet
и DropdownMenu; не реализовывать собственный focus trap/listbox в потребителях.
Выбор инстанса/персонажа использует shadcn Combobox. DateInput сохраняет прежний
текстовый формат и добавляет Popover + Calendar; выбор дня не очищает время.
Sidebar и skeleton используют общие shadcn-примитивы. Локализация и touch-размеры
применяются в адаптерах, финансовый parser и prefill не меняются.

На `/calendar` основная область — месячная сетка Пн–Вс. Походы группы всегда
показываются выше справочных откатов, в том числе в мобильной сводке дня.
Если в этот день записан поход, откат того же инстанса или общего семейства скрыт
в ячейке. Откаты других инстансов остаются. Подпись тоггла соответствует действию:
«Показывать откаты» / «Скрыть откаты».
По умолчанию откаты скрыты; «Показывать откаты» управляет только отображением,
сохраняется в URL и не создаёт записей в БД. Счётчик «Ещё» остаётся внутри ячейки.
Нажатие на день открывает правую выезжающую панель, на мобильном — полноэкранную.
«Расписание откатов» открывает статическую недельную таблицу. Предупреждения
о незакрытых инстансах независимы от фильтров и выбранного месяца.

## Проверка изменений

Для изменённого экрана снять и открыть desktop/mobile screenshots с одинаковыми
данными и viewport до/после. Оценить иерархию, плотность, отступы, текст, действия,
переносы и clipping. При найденной проблеме выполнить correction pass и переснять.

Проверять 1440/390 px для основных экранов, 320/768/1024 px для shell и сложной
композиции. Проверять клавиатуру, формы и доступность точных сумм. Не отправлять
тестовые продажи, выплаты или очистку на рабочей базе. Отдельно проверять empty,
loading, error, success и pending на безопасных данных.

Lint/build/tests дополняют визуальную проверку. Не заявлять WCAG-conformance,
проверку screen reader или поведенческих состояний без фактической проверки.
В постоянной документации хранить правила и ограничения, не историю итераций,
скриншоты прогресса или журнал одобрений.
